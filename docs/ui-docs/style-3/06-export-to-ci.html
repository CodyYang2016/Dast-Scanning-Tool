Make dvwa scans run on their own

Three steps. We don't run anything on a schedule ourselves — your repository does, using a file we give you.

Step 1 of 3

When should it run?

Step 2 of 3

Add the test account as secrets

In the repository's settings, add two secrets: DVWA_USER and DVWA_PASS. We never see their values.

Step 3 of 3

Add this file to the repository

Save it as .github/workflows/dast-dvwa.yml.

name: dast-dvwa
on:
  schedule: [{ cron: "0 6 * * 1" }]
  workflow_dispatch:
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: echo "ZAP_API_KEY=$(openssl rand -hex 24)" >> "$GITHUB_ENV"
      - run: docker compose up -d zap
      - env: { DVWA_USER: ${{ secrets.DVWA_USER }}, DVWA_PASS: ${{ secrets.DVWA_PASS }} }
        run: |
          python -m dast author dvwa --no-llm
          python -m dast scan   dvwa
      - run: python -m dast report dvwa --upload --ref "$DEPLOYED_REF" --commit "$DEPLOYED_SHA"

What a red or green run means

GreenThe scan was healthy and found nothing new that's serious
Red, "gate failed"Something new and serious was found, or the scan wasn't healthy
Red, "refused"A safety check stopped it before anything was sent
=Set once by the platform team, never asked hereThe package mirror, the company's certificate file and the exact scanner version are part of the installation, not part of a scan.
